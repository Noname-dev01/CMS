# CLAUDE.md — com.cms.publicweb.home

> **경로 표기 주의(2026-10-13, PR ②)**: 이 문서의 `/notices`·`/boards`·`/pages`·`/faq`·`/inquiry`·`/`(공개 메인) 표기는 이전 경로다 — 공개 경로는 이제 `/{siteKey}/…` 아래(예: `/main/notices/1`)이고 `/`는 기본 공개 사이트로 302한다. 사이트 해석·404 계약·링크 접두어(`${sitePrefix}`)·시험은 `support/CLAUDE.md` 참조. 이미지(`/banners/{id}/image`·`/popups/{id}/image`·`/content-images/{id}`)는 사이트 무관 경로 그대로다.

이 디렉터리(공개/비로그인 메인 화면 `/`)와 형제 패키지 `com.cms.publicweb.banner`(배너 이미지 공개 다운로드) 작업 시에만 로드된다. 공통 규칙은 프로젝트 루트 `CLAUDE.md` 참조. 설계 근거·적대적 리뷰 5라운드 기록은 `adversarial-review/plan/PLAN-public-home-banner.md`. 관리 측은 `com.cms.admin.banner`의 `CLAUDE.md`. 공개 게시판·공지(`com.cms.publicweb.board`)와 같은 격리·404 흡수 원칙이다.

(필드 목록은 코드가 원본이다. 여기에는 코드만 봐서는 알기 어려운 사실만 기록한다.)

- **`GET /`는 정확 경로 1개만 무인증 공개**(2026-10-09 승인): `SecurityConfig`가 `/`의 GET·HEAD만 `permitAll`, 그 외 메서드는 `denyAll`이다. `/**`를 열지 않았으므로 `/index.html`·`/home` 같은 다른 경로는 기본 거부 그대로다(`SecurityConfigTest`). 이전에는 비로그인 `/`가 로그인으로 302됐다. `HomeController`는 `@AdminPage`를 붙이지 않는다(공개 요청마다 사이드바 메뉴 조회가 나가지 않게). 로그인한 관리자가 `/`에 가도 같은 공개 메인이다(관리자 분기 없음).
- **섹션 3개**(`PublicHomeService`): **배너**(`PublicBannerService.findDisplayableBanners` — `useYn ∧ [start, end)`, `ord, id` 순), **공지**(공지 게시판 `board_key='NOTICE'`의 공개 글 최신 5건, 링크 `/notices/{id}` — 기존 공개 URL 유지), **새 글**(공지 게시판을 **제외한** 공개 게시판의 공개 글 최신 5건 + 게시판 이름, 링크 `/boards/{boardId}/posts/{postId}` — 같은 글이 두 섹션에 나오지 않는다). 공지 게시판이 없거나 비공개·삭제면 공지 섹션만 빠진다 — 메인의 부속 섹션이라 `/notices`와 달리 404/500으로 번역하지 않는다(fail-soft).
- **공개 불변식은 쿼리에 고정**: 최신 글은 `PostRepositoryImpl.findLatestPublished`(게시판 `publicYn ∧ ¬deleted` ∧ 게시글 `useYn ∧ ¬deleted`를 **한 조건 객체**로, 본문 MEDIUMTEXT는 읽지 않는 DTO 프로젝션 `PublishedPostRow`)가, 배너는 `BannerRepository.findDisplayable`·`findDisplayableById`(메서드·쿼리가 조건을 고정)가 맡는다. 호출은 이 패키지 서비스 한 곳에서만 한다. **노출 기간 `[publishStart, publishEnd)`(로드맵 ④, 2026-10-11)도 이 쿼리에 고정돼 있고 `PublicHomeService`가 요청당 1회 산출한 `now`를 공지·새 글 두 쿼리에 같이 넘긴다**(경계에서 두 섹션이 어긋나지 않게). 비용: 5만 행(공개 3개·비공개 2개·공지 게시판 + 미노출·삭제 혼합) 실측 — 새 글 쿼리 ≈ 36ms(전체 공개 게시판 임시 테이블 정렬), 공지 쿼리 ≈ 0.3ms(`idx_post_board_deleted_use_create`), 합 50ms 기준 안. 공개 행이 10만 단위를 넘으면 `(deleted, use_yn, create_date)` 류 전역 최신 글 인덱스를 재평가한다(추측성 인덱스는 추가하지 않았다).
- **템플릿**(`templates/public/home.html` + `static/css/public/home.css`): **`th:utext`·인라인 비이스케이프·`<script>`·`storageKey` 금지**(`PublicHomeTemplateConventionTest` — 메인은 본문 HTML을 출력하지 않고 제목·게시판 이름·배너 제목은 모두 `th:text`/`th:alt`). 첫 배너만 `loading="eager"`, 나머지 `lazy`(리뷰 R1-3). 링크는 `PublicBanner`가 `SafeUrls`로 걸러 준 값만 `th:href`에 들어가고(DB 직접 수정으로 들어간 `javascript:`는 링크 없는 배너로 그려진다 — 실기 확인) 외부 http(s)는 `target="_blank" rel="noopener noreferrer"`.
- **레이어 팝업(2026-10-12, `PLAN-popup.md`) — 메인의 "비이스케이프 출력·스크립트 없음" 규약은 그대로 두고 팝업을 별도 조각으로 분리했다**: `templates/public/fragments/home-popups.html`(+ `static/js/public/home-popup.js`·`home.css`의 `.home-popup*`). `home.html`은 `<th:block th:if="${not #lists.isEmpty(popups)}">`로 감싼 `th:replace`로 **포함만** 한다(`PublicHomeTemplateConventionTest`는 변하지 않았다). 조각의 규약은 `PublicHomePopupTemplateConventionTest`가 고정한다: `th:utext`는 **정확히 1곳이고 `${popup.bodyHtml}`만**(출력 시 `sanitizeForPopupOutput`으로 한 번 더 정리된 값 — `PublicPopup.from`), 스크립트는 외부 파일 1개뿐(인라인 본문·`on*` 속성 없음), **`<img>`는 `src`가 아니라 `data-src`로만**, 팝업 요소는 `hidden`으로 시작, CSS는 `.home-popup[hidden]{display:none !important}`이고 flex 레이아웃은 `.home-popup:not([hidden])`에만(작성자 CSS의 `display:flex`가 `hidden`을 덮어쓰면 스크립트 없이도 팝업이 보인다 — 리뷰 R2-1).
  - **조회는 `HomeController`가 `getHome()`과 별도 호출로 하고 예외를 격리한다**(푸터와 같은 이유 — 메인 읽기 트랜잭션이 rollback-only가 되지 않게). 팝업이 실패하면 팝업만 빠지고 메인은 200이다(`PublicHomePopupIsolationIntegrationTest`가 서비스에 DB 예외를 주입해 고정). `PublicHomeView`는 건드리지 않고 컨트롤러가 모델 `popups`를 따로 넣는다. 노출 중인 팝업을 **등록 순서(`id` 오름차순)로 최대 5개**(`PublicPopupService.MAX_DISPLAYED`).
  - **스크립트의 계약**: 서버는 팝업을 숨김으로 그리고 스크립트가 "오늘 하루 보지 않기" 상태가 아닌 것만 연다. 이때 처음 `data-src`→`src`로 이미지를 내려받는다 — `loading="lazy"`는 스크립트가 꺼지면 적용되지 않아 숨겨진 이미지를 내려받을 수 있기 때문이다(리뷰 R1-4). 스크립트가 없거나 실패하면 팝업이 뜨지 않는다(안전한 쪽으로 실패). 숨김 상태는 `localStorage` `cms.popup.hide.{id}` = `{v: revision, until: 다음 로컬 자정}`이고 접근은 모두 try/catch다. `v`가 `data-version`(= `popup.revision`)과 다르면 무시하고 다시 보인다.
  - **화면 안 유지**: 가로·세로 모두 CSS가 클램프한다. 머리(40px)·바닥(48px)은 `flex:none`, 제목은 한 줄 말줄임이라 200자 제목도 머리를 키우지 못한다 — 내용 영역만 줄어들며 스크롤된다.
- **팝업 이미지 `GET·HEAD /popups/{id}/image`**(`com.cms.publicweb.popup.PublicPopupImageController`): `SecurityConfig`가 이 경로의 GET·HEAD만 공개(2026-10-12 승인)하고 `/popups`·`/popups/**`의 나머지는 `denyAll`. 배너 이미지와 같은 구조(문자열 `id` 직접 파싱, 조회 트랜잭션 / 파일 열기 트랜잭션 없음 분리, `PublicImageStreamer`, `nosniff`·`no-store`)이며 **HTML형 팝업의 이미지 요청도 비노출·없는 ID와 같은 404**다(쿼리 `findDisplayableImageById`가 종류를 조건으로 가진다). 레이트리밋 `popup-image` 120/60초. 상세는 `com.cms.admin.popup`의 `CLAUDE.md`.
- **배너 이미지 `GET·HEAD /banners/{id}/image`**(`PublicBannerImageController`): `SecurityConfig`가 이 경로의 GET·HEAD만 공개하고 `/banners`·`/banners/**`의 나머지는 `denyAll`. `id`는 문자열로 받아 직접 파싱해 **비숫자·0·음수·범위 밖·없는 ID·비노출·시작 전·종료 후·파일 없음이 모두 같은 404**(존재 여부 비노출 — 컨트롤러는 예외를 던지지 않는다, 던지면 404가 아니라 HTML 500). 조회(트랜잭션, `findDisplayableImage`)와 파일 열기(트랜잭션 없음, `open` — `FileStorage.open(key, "banner")` 네임스페이스 스트리밍)를 분리해 `spring.jpa.open-in-view: false` 계약을 지킨다. 응답은 저장된 `image/*` 인라인 + `nosniff` + **`no-store`**(숨긴 배너가 클라이언트 캐시에 남지 않게 — 대가로 메인 조회마다 이미지를 다시 받는다, 개수 상한 10·2MB·레이트리밋으로 제한).
- **스트리밍 응답 공통부는 `publicweb/support/PublicImageStreamer`**(첫 청크 선읽기 → 헤더 → 전송, 전송 중 `IOException`은 **미커밋일 때만 `reset()`** 후 재던짐): 배너가 먼저 쓰고 ⑦ 팝업이 재사용한다. 기존 `PublicContentImageController`·`PublicNoticeController`의 복제 코드는 건드리지 않았다(통합은 후속). 실서버 시험 `PublicBannerImageStreamingServerTest`가 골든 패스·HEAD·**전송 중 DB 커넥션 0(OSIV 회귀 가드)**·첫 청크 실패 HTML 500·미커밋 reset·커밋 후 연결 중단을 고정한다.
- **레이트리밋**(`application.yml`): `public-home` `/` GET·HEAD 120/60초, `banner-image` `/banners/*/image` 240/60초(메인 1회에 최대 10장이라 메인 로드 24회분 — **공유 IP에서 한도를 넘으면 이미지가 429로 깨질 수 있음을 수용**). 전역 전송량·동시 전송 제한은 없다(기존 공개 엔드포인트와 같다). 실기: 병렬 300회 버스트에서 `/` 133건 200 + 167건 429, 이미지 500회에서 283건 200 + 217건 429.
- **예외**: `PublicWebExceptionAdvice`(`com.cms.publicweb` 한정)가 HTML 500(`public/notice/error` 뷰 공유). 렌더링 단계 예외는 이 advice가 못 잡는 기존 한계가 있다.
- 시험: `PublicHomeIntegrationTest`(공지/새 글 분리·공개 불변식·공지 게시판 비공개 시 섹션 제거·5건/최신순/이스케이프)·`PublicHomeTemplateConventionTest`·`PublicBannerImageStreamingServerTest`·`BannerApiIntegrationTest`의 공개 이미지·메인 시험·`PostRepositoryDataJpaTest`의 `findLatestPublished` 시험·`SecurityConfigTest`의 `/`·`/banners` 계약.
