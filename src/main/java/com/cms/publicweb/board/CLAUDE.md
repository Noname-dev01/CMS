# CLAUDE.md — com.cms.publicweb.board

> **경로 표기 주의(2026-10-13, PR ②)**: 이 문서의 `/notices`·`/boards`·`/pages`·`/faq`·`/inquiry`·`/`(공개 메인) 표기는 이전 경로다 — 공개 경로는 이제 `/{siteKey}/…` 아래(예: `/main/notices/1`)이고 `/`는 기본 공개 사이트로 302한다. 사이트 해석·404 계약·링크 접두어(`${sitePrefix}`)·시험은 `support/CLAUDE.md` 참조. 이미지(`/banners/{id}/image`·`/popups/{id}/image`·`/content-images/{id}`)는 사이트 무관 경로 그대로다.

이 디렉터리(공개/비로그인 게시판 화면) 작업 시에만 로드된다. 공통 규칙은 프로젝트 루트 `CLAUDE.md` 참조. 관리자 측 게시판·게시글 도메인은 `com.cms.admin.board`의 `CLAUDE.md`, 설계 근거·적대적 리뷰 기록은 `adversarial-review/plan/PLAN-board.md`(쟁점 10). 공개 공지(`com.cms.publicweb.notice`)와 같은 격리·404 흡수·스트리밍 구조다 — 공지는 2026-10-09부터 공지 게시판의 게시글이라 `/notices/**`는 이 서비스(`PublicBoardService`)에 위임한다(`PublicNoticeService`는 얇은 어댑터).

(필드 목록은 엔티티 코드가 원본이다. 여기에는 코드만 봐서는 알기 어려운 사실만 기록한다.)

- **라우트**(`PublicBoardController`, 2026-10-08): `GET /boards/{boardId}`(목록 + `keyword` 제목 검색, 페이지 크기는 게시판 설정 10·20·30·50 — 기본 10) · `GET /boards/{boardId}/posts/{postId}`(상세) · `GET·HEAD /boards/{boardId}/posts/{postId}/attachments/{attachmentId}`(스트리밍 다운로드). 게시판 색인(`/boards`)은 없다(범위 밖 — 핸들러가 없어 HTML 404).
- **공개 불변식은 `PublicBoardService` 한 곳에 격리**: 게시판 `publicYn=true ∧ deleted=false` ∧ 게시글 `useYn=true ∧ deleted=false` ∧ **게시글의 노출 기간 `[publishStart, publishEnd)` 안**(2026-10-11 로드맵 ④ — 한쪽 null이면 그쪽 열림, 판정 시각은 주입된 KST `Clock`을 메서드 호출당 1회 산출해 쿼리에 넘긴다) ∧ **게시글이 그 게시판 소속**. 관리 서비스(`PostService`)를 재사용하지 않는다. 게시판 조회는 `findByIdAndDeletedFalseAndPublicYnTrue`, 게시글은 `findPublishedById(id, boardId, now)`(JPQL이 조건을 고정 — 시각 없는 옛 메서드는 제거됐다), 목록은 QueryDSL `PostRepositoryImpl.searchPublished(…, now, …)`가 **SELECT와 COUNT에 같은 조건 객체**를 쓴다(COUNT에서 공개 조건이 빠지면 숨김 글의 존재가 총 페이지 수로 드러난다 — `PublicBoardIntegrationTest.paginationCountsOnlyPublished`). 비공개·삭제 게시판, 미노출·삭제·다른 게시판 소속 게시글, 없는 ID, 비숫자 ID는 **모두 같은 404**다(존재 여부 비노출). 첨부는 `(attachmentId, postId)` 조합으로 조회해 다른 게시글의 첨부 ID도 404.
- **경로 변수는 문자열로 받아 직접 파싱**한다(`boardId`·`postId`·`attachmentId`·`page`) — Spring 타입 변환 실패가 전역 `GlobalApiExceptionHandler`에서 JSON이 되는 것을 피한다. 파싱 실패는 404/0으로 흡수. 컨트롤러는 예외를 던지지 않는다(던지면 404가 아니라 HTML 500). 남은 예외는 `PublicWebExceptionAdvice`가 HTML 500(**공지의 `public/notice/error` 뷰를 공유** — 별도 오류 뷰를 만들지 않는다).
- **본문 HTML 출력**: 상세 본문은 `th:utext="${post.content}"` — 공개 게시판 템플릿에서 이스케이프 없는 출력은 **이 한 곳만** 허용되고 `PublicBoardTemplateConventionTest`가 고정한다(제목·게시판 이름·첨부 파일명은 `th:text`). 값은 `PublicPostDetail.from`이 `HtmlContentSanitizer`로 정리한 HTML이라 DTO를 빌더로 직접 만들어 원문을 넣지 않는다. 공개 DTO는 `authorId`·`useYn`을 필드 자체에서 제외하고, 첨부 DTO는 `storageKey`·`contentType`을 제외한다(`PublicPostAttachmentRef`만 `storageKey`를 가지며 Model·뷰에 넣지 않는다).
- **첨부 다운로드 스트리밍**: 조회(트랜잭션, `findPublishedAttachment`)와 파일 열기(트랜잭션 없음, `openAttachment`)를 분리해 열린 스트림이 트랜잭션 프록시를 통과하지 않게 한다. 4KB 버퍼, `octet-stream`·`attachment`·`nosniff`·`no-store`, HEAD 전용 핸들러(GET과 같은 경로로 404 판정, 본문은 읽지 않음). 실패 처리는 공지와 같은 3구간(응답 무손대 → HTML 500 / 미커밋 오염 → `reset()` 후 HTML 500 / 커밋 후 → 연결 중단)이며 코드는 공지 컨트롤러의 복제다 — **한쪽을 고치면 다른 쪽과 `PublicBoardAttachmentStreamingServerTest`·`PublicAttachmentStreamingServerTest`(실서버 Tomcat)를 함께 본다**(`spring.jpa.open-in-view: false`가 켜져 있어야 전송 중 DB 커넥션을 쥐지 않는다).
- **`SecurityConfig`·레이트리밋**(2026-10-08 승인): `/boards`·`/boards/**`는 GET·HEAD만 `permitAll`, 나머지 메서드는 `denyAll`(CSRF 없으면 403, 있으면 익명 302/인증 403 — `SecurityConfigTest`). 새 라우트는 이 매처가 하위 전체를 포괄하므로 코드 추가만으로 무인증 공개가 된다 — 접근 통제는 전량 `PublicBoardService`의 조건이 담당한다. `application.yml` 규칙 `board-attachment`(`/boards/*/posts/*/attachments/*` 20/60초)가 `public-board`(`/boards/**` 120/60초)보다 **먼저** 평가된다(더 엄격한 한도 우선, 순서 변경 금지).
- **화면**: `templates/public/board/{list,detail}.html` + `static/css/public/board.css`(공지 CSS를 복사해 접두어만 바꾼 독립 파일 — 공지가 ①-2에서 게시판으로 흡수됐지만 공개 /notices 화면은 URL·템플릿 계약 유지를 위해 `notice.css`·`public/notice/*`를 그대로 두었으므로 CSS 공통화는 별도 정리 작업으로 판단한다). 본문 표시 CSS는 편집기와 같게 `pre-wrap` + 문단 여백 0.
- **본문 이미지 공개**(`/content-images/{id}`, `com.cms.publicweb.contentimage`): 공개 게시글이 참조할 때만 익명 200이고(`existsPublishedPostRef` — **`r.imageId = :imageId` 조건이 빠지면 다른 공개 글의 참조가 아무 이미지나 공개한다**, 리뷰 R1-1이 잡았고 `PublicBoardIntegrationTest.unreferencedImageStaysHiddenEvenWhenAnotherImageIsPublished`가 고정), 게시판 출처 이미지는 그 게시판의 **현재** READ 권한자(ADMIN 포함)에게만 미참조 상태로 보인다. 공개 조건(게시판 `publicYn ∧ ¬deleted`, 게시글 `useYn ∧ ¬deleted ∧ 노출 기간 안`)을 바꾸면 `ContentImageRefRepository.existsPublishedPostRef(imageId, now)`도 함께 바꾼다 — 기간 조건이 빠지면 예약·만료 글은 404인데 그 글의 이미지가 미리/오래 공개된다(`PostPublishPeriodPublicIntegrationTest`가 익명 GET·HEAD·공유 이미지·READ 권한자 미리보기로 고정).
- 시험: `PublicBoardIntegrationTest`(목록·COUNT·검색·상세·첨부 불변식, XSS 이스케이프, 비-GET 거부, 이미지 공개 판정 — 실제 스택, 요청마다 고유 원격 IP로 레이트리밋 버킷 격리), `PublicBoardAttachmentStreamingServerTest`(실서버 스트리밍·OSIV 가드), `PublicBoardTemplateConventionTest`, `SecurityConfigTest`.
- **조회수·다운로드 수 집계(2026-10-13)**: 상세 GET(공개 판정 통과 후, HEAD 제외)과 첨부 다운로드 GET(파일 열기 성공 후, `try-with-resources` 안, HEAD 제외)이 `ContentCounterService`를 부른다 — 예외를 던지지 않으므로 스트리밍 3구간 실패 처리에 영향이 없다. `PublicNoticeController`에도 같은 호출이 복제돼 있으니 한쪽을 고치면 다른 쪽도 본다. 규칙·한계는 `com.cms.admin.board`의 `CLAUDE.md`.
- **사이트별 게시판(PR ④, 2026-10-14)**: 게시판이 현재 사이트에 보이려면 `publicYn ∧ ¬deleted ∧ (site_id IS NULL ∨ site_id = 현재 사이트)`다 — `PublicBoardService`의 세 메서드(`getPublishedPosts`·`findPublishedPost`·`findPublishedAttachment`)가 `siteId`를 **첫 인자로 필수** 받고(`PublicSite.requireId`) `BoardRepository.findPublicById(boardId, siteId)`가 조건을 쿼리에 고정한다. 컨트롤러는 `PublicSiteRoutes.current(request).id()`를 넘긴다(첨부 HEAD 핸들러도 `request`를 받는다). 다른 사이트 전용 게시판의 목록·상세·첨부는 비공개·없는 ID와 **같은 404**다(`PublicBoardSiteScopeIntegrationTest`). 본문 이미지는 사이트 무관 경로이고 소속 사이트가 비활성이면 404. 상세는 `com.cms.admin.site`의 `CLAUDE.md` "사이트별 게시판·공지".
