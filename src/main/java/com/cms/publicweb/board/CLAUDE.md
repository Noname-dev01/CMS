# CLAUDE.md — com.cms.publicweb.board

> **경로 표기 주의(2026-10-13, PR ②)**: 이 문서의 `/notices`·`/boards`·`/pages`·`/faq`·`/inquiry`·`/`(공개 메인) 표기는 이전 경로다 — 공개 경로는 이제 `/{siteKey}/…` 아래(예: `/main/notices/1`)이고 `/`는 기본 공개 사이트로 302한다. 사이트 해석·404 계약·링크 접두어(`${sitePrefix}`)·시험은 `support/CLAUDE.md` 참조. 이미지(`/banners/{id}/image`·`/popups/{id}/image`·`/content-images/{id}`)는 사이트 무관 경로 그대로다.

이 디렉터리(공개/비로그인 게시판 화면) 작업 시에만 로드된다. 공통 규칙은 프로젝트 루트 `CLAUDE.md` 참조. 관리자 측 게시판·게시글 도메인은 `com.cms.admin.board`의 `CLAUDE.md`, 설계 근거·적대적 리뷰 기록은 `adversarial-review/plan/PLAN-board.md`(쟁점 10). 공지는 공지 게시판의 게시글이고 **2026-10-28(PR 4b)부터 공개 공지도 이 화면 한 벌**이다 — `/{siteKey}/notices`는 공지 게시판으로 302만 하고(`com.cms.publicweb.notice`, 대상은 `PublicBoardService.findNoticeBoardSlug`), 공지 전용 컨트롤러·서비스·템플릿·`notice.css`는 지웠다.

(필드 목록은 엔티티 코드가 원본이다. 여기에는 코드만 봐서는 알기 어려운 사실만 기록한다.)

- **게시판 세그먼트는 슬러그다(2026-10-28, PR 4a)**: 라우트 변수는 `{boardSlug}`이고 `PublicBoardService.resolveBoard(siteId, segment)`가 `Found(id)`/`Moved(slug)`/`NotFound`로 해석한다 — 기본 슬러그 `board-{id}`(정규형만) → 사용자 슬러그 형식 → 그 밖(숫자 id·대문자·형식 위반) 404. 공개 조건(`findPublicById`·`findPublicBySlug`)을 먼저 통과해야 하므로 비공개·삭제·다른 사이트 게시판은 301 없이 같은 404다(새 슬러그 비노출). **슬러그를 바꾼 게시판의 `board-{id}`는 301** — `Location`은 원문을 잘라 붙이지 않고 서버가 다시 만든다(현재 사이트 키·새 슬러그·`PathIds` 정규형 게시글/첨부 id + 원래 쿼리스트링), 게시글·첨부 id가 읽히지 않으면 301 없이 404. 301은 `response`에 직접 쓰고 `null`을 돌려준다(`HttpServletResponse` 인자가 있어 뷰를 찾지 않는다). 301 응답은 조회수·다운로드 수를 세지 않는다. 해석과 이후 조회는 다른 트랜잭션이다(쿼리 1회 추가, 사이의 비공개 전환은 기존과 같은 약한 보장). 링크는 DTO의 `boardSlug`(`PublicBoardListResult`·`PublicPostDetail`, 메인 `PublicHomePost`)로 만든다 — 템플릿에 `boardId`로 공개 주소를 만들지 않는다. 시험 `PublicBoardSlugIntegrationTest`. 규칙의 원본은 `com.cms.admin.board`의 `CLAUDE.md` "게시판 슬러그".
- **라우트**(`PublicBoardController`, 2026-10-08 — 아래의 `{boardId}`는 PR 4a부터 슬러그): `GET /boards/{boardId}`(목록 + `keyword` 제목 검색, 페이지 크기는 게시판 설정 10·20·30·50 — 기본 10) · `GET /boards/{boardId}/posts/{postId}`(상세) · `GET·HEAD /boards/{boardId}/posts/{postId}/attachments/{attachmentId}`(스트리밍 다운로드). 게시판 색인(`/boards`)은 없다(범위 밖 — 핸들러가 없어 HTML 404).
- **공개 불변식은 `PublicBoardService` 한 곳에 격리**: 게시판 `publicYn=true ∧ deleted=false` ∧ 게시글 `useYn=true ∧ deleted=false` ∧ **게시글의 노출 기간 `[publishStart, publishEnd)` 안**(2026-10-11 로드맵 ④ — 한쪽 null이면 그쪽 열림, 판정 시각은 주입된 KST `Clock`을 메서드 호출당 1회 산출해 쿼리에 넘긴다) ∧ **게시글이 그 게시판 소속**. 관리 서비스(`PostService`)를 재사용하지 않는다. 게시판 조회는 `findByIdAndDeletedFalseAndPublicYnTrue`, 게시글은 `findPublishedById(id, boardId, now)`(JPQL이 조건을 고정 — 시각 없는 옛 메서드는 제거됐다), 목록은 QueryDSL `PostRepositoryImpl.searchPublished(…, now, …)`가 **SELECT와 COUNT에 같은 조건 객체**를 쓴다(COUNT에서 공개 조건이 빠지면 숨김 글의 존재가 총 페이지 수로 드러난다 — `PublicBoardIntegrationTest.paginationCountsOnlyPublished`). 비공개·삭제 게시판, 미노출·삭제·다른 게시판 소속 게시글, 없는 ID, 비숫자 ID는 **모두 같은 404**다(존재 여부 비노출). 첨부는 `(attachmentId, postId)` 조합으로 조회해 다른 게시글의 첨부 ID도 404.
- **경로 변수는 문자열로 받아 직접 파싱**한다(`boardId`·`postId`·`attachmentId`·`page`) — Spring 타입 변환 실패가 전역 `GlobalApiExceptionHandler`에서 JSON이 되는 것을 피한다. 파싱 실패는 404/0으로 흡수. 컨트롤러는 예외를 던지지 않는다(던지면 404가 아니라 HTML 500). 남은 예외는 `PublicWebExceptionAdvice`가 HTML 500(**공용 `public/error` 뷰** — PR 4b에서 `public/notice/error`를 옮겼다, 별도 오류 뷰를 만들지 않는다).
- **본문 HTML 출력**: 상세 본문은 `th:utext="${post.content}"` — 공개 게시판 템플릿에서 이스케이프 없는 출력은 **이 한 곳만** 허용되고 `PublicBoardTemplateConventionTest`가 고정한다(제목·게시판 이름·첨부 파일명은 `th:text`). 값은 `PublicPostDetail.from`이 `HtmlContentSanitizer`로 정리한 HTML이라 DTO를 빌더로 직접 만들어 원문을 넣지 않는다. 공개 DTO는 `authorId`·`useYn`을 필드 자체에서 제외하고, 첨부 DTO는 `storageKey`·`contentType`을 제외한다(`PublicPostAttachmentRef`만 `storageKey`를 가지며 Model·뷰에 넣지 않는다).
- **첨부 다운로드 스트리밍**: 조회(트랜잭션, `findPublishedAttachment`)와 파일 열기(트랜잭션 없음, `openAttachment`)를 분리해 열린 스트림이 트랜잭션 프록시를 통과하지 않게 한다. 4KB 버퍼, `octet-stream`·`attachment`·`nosniff`·`no-store`, HEAD 전용 핸들러(GET과 같은 경로로 404 판정, 본문은 읽지 않음). 실패 처리는 3구간(응답 무손대 → HTML 500 / 미커밋 오염 → `reset()` 후 HTML 500 / 커밋 후 → 연결 중단)이다 — 공지 컨트롤러의 복제는 PR 4b에서 사라졌고 **고칠 때 `PublicBoardAttachmentStreamingServerTest`(실서버 Tomcat, OSIV 가드 포함)를 본다**(`spring.jpa.open-in-view: false`가 켜져 있어야 전송 중 DB 커넥션을 쥐지 않는다).
- **`SecurityConfig`·레이트리밋**(2026-10-08 승인): `/boards`·`/boards/**`는 GET·HEAD만 `permitAll`, 나머지 메서드는 `denyAll`(CSRF 없으면 403, 있으면 익명 302/인증 403 — `SecurityConfigTest`). 새 라우트는 이 매처가 하위 전체를 포괄하므로 코드 추가만으로 무인증 공개가 된다 — 접근 통제는 전량 `PublicBoardService`의 조건이 담당한다. `application.yml` 규칙 `board-attachment`(`/boards/*/posts/*/attachments/*` 20/60초)가 `public-board`(`/boards/**` 120/60초)보다 **먼저** 평가된다(더 엄격한 한도 우선, 순서 변경 금지).
- **화면**: `templates/public/board/{list,detail}.html` + `static/css/public/board.css`(공지 게시판도 이 화면을 쓴다 — 공지 전용 `notice.css`·`public/notice/*`는 PR 4b에서 지웠다. 제목 영역은 게시판 이름이다). 본문 표시 CSS는 편집기와 같게 `pre-wrap` + 문단 여백 0.
- **본문 이미지 공개**(`/content-images/{id}`, `com.cms.publicweb.contentimage`): 공개 게시글이 참조할 때만 익명 200이고(`existsPublishedPostRef` — **`r.imageId = :imageId` 조건이 빠지면 다른 공개 글의 참조가 아무 이미지나 공개한다**, 리뷰 R1-1이 잡았고 `PublicBoardIntegrationTest.unreferencedImageStaysHiddenEvenWhenAnotherImageIsPublished`가 고정), 게시판 출처 이미지는 그 게시판의 **현재** READ 권한자(ADMIN 포함)에게만 미참조 상태로 보인다. 공개 조건(게시판 `publicYn ∧ ¬deleted`, 게시글 `useYn ∧ ¬deleted ∧ 노출 기간 안`)을 바꾸면 `ContentImageRefRepository.existsPublishedPostRef(imageId, now)`도 함께 바꾼다 — 기간 조건이 빠지면 예약·만료 글은 404인데 그 글의 이미지가 미리/오래 공개된다(`PostPublishPeriodPublicIntegrationTest`가 익명 GET·HEAD·공유 이미지·READ 권한자 미리보기로 고정).

- **게시판 유형별 목록(PR 6, 2026-10-29)**: `list.html` **한 파일** 안에서 일반 글 목록만 `boardType`(모델 문자열 `LIST`·`GALLERY`·`WEBZINE`)으로 분기한다 — 머리·설명·검색 폼·**고정 영역(모든 유형에서 목록형 한 줄)**·빈 목록 문구·페이지 이동은 공유한다. `PublicBoardListResult.boardType`은 `Board.type()`(해석값 — 알 수 없는 저장값은 `LIST`)이고, `PublicPostSummary`에 `coverImageId`(항상)·`excerpt`(웹진형 일반 목록만, 고정 영역은 null)가 더해졌다. **썸네일**은 대표가 있는 글만 `<img src="/content-images/{id}?size=thumb" alt="" loading="lazy" decoding="async">`이고(사이트 무관 경로라 `sitePrefix` 없음, 대표는 그 글이 참조하는 이미지라 공개 판정이 원본과 같다), 대표 없는 글은 **CSS 자리표시**(`board-thumb-empty` — 단색 바탕 가운데 사진 아이콘, 아이콘은 CSS 안의 SVG data URI라 이미지 요청·정적 파일 없음. 이미지 한도로 썸네일이 실패한 순간에도 보이게 하려는 것이라 외부 이미지 파일로 바꾸지 않는다). **썸네일이 실패하면(429 한도 초과·404 비공개 전환/파일 유실·500) 외부 스크립트 `/js/public/board-thumb-fallback.js`가 같은 자리표시로 바꾼다**(2026-10-29 후속) — `<head>`에 `defer` 없이 두어 이미지 요청보다 먼저 `document`의 **캡처 단계** `error` 리스너가 붙는다(`error`는 버블링되지 않는다. 지연 로딩으로 스크롤할 때 늦게 실패하는 칸도 이 리스너가 잡는다 — `DOMContentLoaded` 정리만으로는 못 잡는 것을 변이 실험으로 확인). `DOMContentLoaded` 정리는 `complete ∧ naturalWidth 0`만 바꾼다 — **`complete` 검사를 빼면 아직 요청 전인 지연 로딩 이미지(Chrome은 `complete=false`)까지 미리 자리표시가 되어 영영 안 뜬다**(변이 실험으로 확인). 원인은 그대로이고 다시 요청하지 않는다(재시도는 한도를 더 쓴다). 스크립트는 썸네일이 있는 유형(`GALLERY`·`WEBZINE`)에만 싣고, 공개 게시판 템플릿의 스크립트는 이 외부 파일 하나뿐이며 인라인 스크립트·인라인 이벤트 속성(`on…=`)은 없다(`PublicBoardTemplateConventionTest`). 시험 `BoardThumbFallbackBrowserTest`(실제 브라우저, 익명 — 관리자는 미리보기 권한으로 이미지를 통과시켜 실패가 재현되지 않는다). **요약(`PostExcerpt`)은 조회 때 추출한다** — 저장된 본문 HTML의 앞 20,000 UTF-16 유닛(서로게이트 쌍은 쪼개지 않는다)을 jsoup으로 읽어 블록·`br` 경계를 공백으로, `&nbsp;`를 일반 공백으로 접고 120 코드 포인트에서 자른 뒤 `…`; 텍스트가 없으면 null(요약 줄 생략). 이미 정리된 본문이고 출력이 `th:text`라 sanitizer를 다시 거치지 않는다. 목록 쿼리가 이미 본문(`content`)을 읽으므로 추가 쿼리가 없다. 템플릿의 `th:utext`는 늘리지 않는다(`PublicBoardTemplateConventionTest` 그대로). 규칙의 원본은 `com.cms.admin.board`의 `CLAUDE.md` "게시판 유형". 시험 `BoardTypePublicIntegrationTest`·`PostExcerptTest`·`BoardThumbFallbackBrowserTest`.
