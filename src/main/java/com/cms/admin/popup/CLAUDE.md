# CLAUDE.md — com.cms.admin.popup

이 디렉터리(공개 메인 레이어 팝업 관리) 작업 시에만 로드된다. 공통 규칙은 프로젝트 루트 `CLAUDE.md` 참조. 설계 결정·적대적 리뷰 5라운드 기록은 `adversarial-review/plan/PLAN-popup.md`(2026-10-12). 공개 측은 `com.cms.publicweb.popup`(이미지 `/popups/{id}/image`)과 공개 메인 `com.cms.publicweb.home`의 `CLAUDE.md`. 자매 기능은 `com.cms.admin.banner`(같은 패턴, 아래 "배너와 다른 점").

(필드 목록은 엔티티 코드가 원본이다. 여기에는 코드만 봐서는 알기 어려운 사실만 기록한다.)

- **권한 — 세 번째 기능 단위 위임(`DELEGABLE`) 기능 `POPUP`**: 핸들러는 전부 `@RequirePermission(feature = POPUP, action = …)` — 목록·상세·**관리자 이미지 보기** = READ, 등록 = CREATE, 수정(`PUT /{id}`) = UPDATE, 삭제 = DELETE. URL 게이트(`/admin/popup/manage`·`/admin/api/popups`·`/admin/api/popups/**`)는 `AdminFeature.POPUP.gatePatterns`에서 `SecurityConfig`의 `DELEGABLE` 루프가 만든다(게이트 쪽 `SecurityConfig` 수정 없음). 배너(`BANNER`)와 권한은 서로 독립이다(`PopupPermissionMatrixIntegrationTest`). 화면 버튼은 `myPermissions`(`"POPUP:CREATE"` 등)로 숨길 뿐 서버 판정(403)이 최종이다. **새 `DELEGABLE` 기능을 추가하면 열거하는 시험이 함께 바뀐다**: `AdminSidebarAdviceSnapshotTest`·`AdminPermissionEvaluatorTest`(ADMIN 전 동작 키)·`MenuExposureSidebarIntegrationTest`(위임 READ 시드는 이제 카탈로그의 `DELEGABLE` 목록에서 생성).
- **종류는 둘이고 불변**: `PopupType.IMAGE`(이미지 한 장 + 선택 링크)와 `HTML`(편집기 본문). 종류 변경·이미지 교체는 없다(삭제 후 재등록 — 이미지 파일 정리 경로가 하나 더 생기는 것을 피했고 ⑧ 미디어 라이브러리에서 해결한다). 종류별 **필수·금지 필드는 서비스가 400으로 강제**한다: 이미지형은 이미지 필수·본문 금지·높이 금지(비율 유지), HTML형은 본문 필수·이미지 금지·링크 금지(링크는 본문 안에서).
- **스키마(V39~V40)**: `popup`(제목·`revision`·`popup_type`·링크·`storage_key`/`content_type`/`file_size`(이미지형)·`content_html`(HTML형, MEDIUMTEXT)·`pos_x`/`pos_y`/`width`/`height`·기간·`use_yn`, **하드 삭제**). **가드 행·`ord`·정확한 개수 상한이 없다**(배너와 다른 점) — 직렬화할 대상이 없기 때문이다. 날짜 컬럼은 `datetime(6)`. 노출은 `use_yn ∧ [display_start, display_end)`(시작 포함·종료 **미포함**), 기간이 비면 그쪽은 열림.
- **`revision` — 수정마다 +1, 반드시 행 락 아래**: 방문자 브라우저의 "오늘 하루 보지 않기"(`localStorage`의 `{v: revision, until}`)가 수정 전 팝업에 대한 것인지 가린다. 수정 시각(초 단위)은 같은 초의 두 번째 수정을 구분하지 못해 쓰지 않는다(리뷰 R1-2). **`PopupRepository.findByIdForUpdate`의 `@Lock(PESSIMISTIC_WRITE)` 선언이 빠지면 동시 수정이 같은 값을 읽어 증가분이 유실된다** — 메서드 이름이 아니라 선언이 락을 만든다. `PopupConcurrencyIntegrationTest`가 `LockWaitObserver`로 실제 락 대기와 `revision == n+2`를 고정하고, 변이 실험(`@Lock` 제거)이 두 시험을 모두 실패시킨다(8스레드 동시 수정이 +8이 아니라 +1에 그친다). 변경 없는 저장도 `revision`을 올린다(단순함 우선 — 방문자에게 팝업이 다시 보일 뿐이다).
- **소프트 상한 30**(`PopupService.MAX_POPUPS`, 초과 409): 관리 화면 비용 제한용이다. 가드 행이 없어 `count` 검사만 하므로 **동시 등록 시 요청 수만큼 넘을 수 있다**(수용). 공개 메인은 노출 중인 팝업을 등록 순서(`id` 오름차순)로 **최대 5개**만 그린다(`PublicPopupService.MAX_DISPLAYED`) — 관리 화면이 노출 중 5개 초과를 경고한다. 목록 응답은 `contentHtml`을 싣지 않고(`PopupResponse.summaryOf`) 수정 화면이 상세 API로 가져온다.
- **이미지(이미지형만)**: png·jpeg·gif, **2MB, 한 변 2560px, 총 4,000,000픽셀**, 헤더 검사만(`ImageFileValidator.Limits`), 애니메이션 거부. 배너의 `LIMITS`는 비공개 상수라 **참조하지 않고 같은 값을 따로 둔다**(한쪽 한도를 바꿔도 다른 쪽이 따라 바뀌지 않게). 저장은 `FileStorage`의 **`popup` 네임스페이스**(예약 네임스페이스 — `LocalDiskFileStorage.RESERVED_NAMESPACES`에 `popup` 추가, 루트 API `load/open/delete`는 `popup/…` 키에 닿지 못한다, `LocalDiskFileStorageTest`). 등록은 롤백 시 정리(`deleteOnRollback`), 삭제는 **커밋 후** 파일 삭제(`deleteAfterCommit`) — `PopupFileCleanupIntegrationTest`가 저장소 계층 예외 주입으로 두 방향을 고정한다. **기존 수동 회수 ⑤는 `popup/`을 제외해야 하고 ⑤-4가 `popup` 테이블로 대조한다**(제외가 없으면 정상 팝업이 고아로 삭제됨 — 롤백 기간에 구버전 ⑤를 실행하면 같은 일이 생긴다, `docs/deployment.md` "공개 메인 팝업").
- **HTML 본문**: `ContentBodyPolicy.sanitizePopup`(이미지 불허, 보이는 글자 2,000자, 정리 후 50,000바이트, 요청 원문 100,000바이트 — `@MaxUtf8Bytes`로 sanitizer가 파싱하기 전에 거른다)과 출력 시 재정리 `sanitizeForPopupOutput`(DB 직접 수정으로 들어온 `script`·`img`·`javascript:`도 렌더하지 않는다, 정리 결과가 비면 `PublicPopup.from`이 팝업을 만들지 않는다). 링크는 sanitizer가 `rel="noopener noreferrer nofollow"`·`target=_blank`를 강제한다. 편집기는 `NoticeEditor.create(…, {allowImages:false})`다.
- **입력 계약 — 필드별 해제 규칙이 다르다**: 등록(multipart)은 폼의 빈 입력란을 "없음"으로 본다. 수정(JSON `PUT`, 전체 교체)은 **링크만 `null`·빈 문자열 모두 해제, 노출 시작·종료·높이는 `null`만 해제하고 빈 문자열은 400**이다. 기간은 `String`으로 받아 `parseKstLocal`(엄격: 오프셋·존재하지 않는 날짜·24:00·소수 초 형식 거부) → `requireInRange`(2000~2099) → `normalize`(분 절단) → `requireValid`(`start < end`) 순서로 검증한다. **Jackson 3.1.7은 `Integer`를 읽을 때 `""`·공백을 `null`로 바꾼다** — 그래서 `PopupUpdateRequest.height`는 세터가 원시 값(`Object`)을 받아 `null`과 정수만 허용한다. 전역 `ObjectMapper` 설정은 다른 API에 영향을 주므로 바꾸지 않았다. 이 DTO에 모든 인자 생성자를 만들지 않는다(Jackson 3은 매개변수 이름으로 생성자를 creator로 인식해 세터를 우회한다).
- **배치(px) 범위**: `pos_x`·`pos_y` 0~2000, `width` 200~1000, `height` 144~1000(HTML형만 — 머리 40 + 내용 최소 48 + 바닥 48 = 136px이라 그보다 낮으면 바닥 버튼이 잘린다, 코드 리뷰 R1). 서비스가 400으로 강제하고(`PopupLimits`), 화면 안 유지는 공개 CSS가 한다(`home.css` — 세로/가로 클램프, 머리·바닥은 `flex:none`).
- **감사**: `POPUP_CREATE`·`POPUP_UPDATE`·`POPUP_DELETE`(`targetType=POPUP`, `targetId`=팝업 ID). 제목·본문은 사용자 입력이라 `targetLabel` 없음. **실패 행의 `errorMessage`는 고정 문구(`safeErrorMessage`)**라 입력한 본문이 감사 테이블에 섞이지 않는다(`PopupApiIntegrationTest.auditFailureMessageIsFixed`). `AdminActionTypes`와 `templates/admin/log/manage.html` 라벨은 동기화 시험이 고정한다.
- **관리자 이미지 보기**(`GET /admin/api/popups/{id}/image`): 공개 경로가 비노출·기간 외 팝업을 404로 막으므로 관리 화면 썸네일은 노출 여부와 무관하게 파일을 읽는 이 전용 엔드포인트를 쓴다(READ 권한, byte[] — 2MB 이하 소수 관리자 요청). HTML형은 404.
- **화면**(`templates/admin/popup/manage.html`): 배너 화면의 날짜 + 시·분 `<select>` 방식과 상태 배지를 따르되 ▲▼·순서 저장은 없다. 종류 라디오(수정 때는 잠금), 이미지형은 업로드란·링크, HTML형은 이미지 없는 편집기·높이. 목록 썸네일은 `loading="lazy"`. 수정은 상세 API를 먼저 불러온다(요청 세대로 늦은 응답 폐기). 저장 중에는 입력·편집기를 잠근다. 제목은 `textContent`로만 삽입.
- **롤백 후 권한 부활**: 팝업 도입 전 앱으로 롤백했다가 재배포하면 이전 앱의 "전체 회수"가 남긴 `POPUP` 행이 되살아난다 — `docs/deployment.md` "공개 메인 팝업"의 정리 트랜잭션이 필수.
- **배너와 다른 점**(복사해서 만들었지만 바뀐 곳): 가드 행(`popup_lock`)·`ord`·순서 저장 없음, 종류 둘, `revision`, 소프트 상한(배너는 정확한 10개), 기간 입력을 `String` + 엄격 파싱 + 범위 검증으로 받음(배너 DTO는 `LocalDateTime` 바인딩이고, 범위 검증(`requireInRange`)은 팝업 PR 중 발견해 별도 PR(#132)로 배너에도 추가했다(그전에는 `0001-01-01` 같은 값이 500이 아니라 201/200으로 그대로 저장됐다) — 엄격 파싱으로의 전환은 아직이다, `com.cms.admin.banner`의 `CLAUDE.md`).
- 시험: `PopupApiIntegrationTest`(생명주기·검증·감사·공개 이미지 404 동일·공개 메인 노출/상한/위험 입력 출력 시 차단)·`PopupPermissionMatrixIntegrationTest`·`PopupConcurrencyIntegrationTest`·`PopupFileCleanupIntegrationTest`·`PopupMigrationTest`·`PopupRepositoryDataJpaTest`, **`PopupAdminFormBrowserTest`(실제 브라우저 — 종류 전환 폼 검증·종류별 입력 상태·높이 범위, `src/test/java`의 `CLAUDE.md` "브라우저 기본 동작")**, 공개 측 `PublicPopupImageStreamingServerTest`(실제 Tomcat·OSIV 가드 — `spring.jpa.open-in-view`를 켜면 "전송 중 DB 커넥션 0" 시험이 실패함을 변이 실험으로 확인)·`PublicHomePopupIsolationIntegrationTest`(팝업 조회 실패 시 메인 정상)·`PublicHomePopupTemplateConventionTest`, 그리고 `SecurityConfigTest`의 `/popups`·팝업 게이트 판.
