# CLAUDE.md — com.cms.admin.faq

이 디렉터리(FAQ 카테고리·FAQ 관리) 작업 시에만 로드된다. 공통 규칙은 프로젝트 루트 `CLAUDE.md` 참조. 설계 결정·적대적 리뷰 6라운드 기록은 `adversarial-review/plan/PLAN-faq.md`(2026-10-12). 공개 측은 `com.cms.publicweb.faq`의 `CLAUDE.md`(공개 `/faq`·즉시 필터).

(필드 목록은 엔티티 코드가 원본이다. 여기에는 코드만 봐서는 알기 어려운 사실만 기록한다.)

- **권한 — 네 번째 기능 단위 위임(`DELEGABLE`) 기능 `FAQ`**: 카테고리와 FAQ가 **한 기능**이다. 핸들러 분류: 트리·FAQ 상세 = READ, 카테고리·FAQ 등록 = CREATE, 수정·**순서 반영(`PUT /order`)** = UPDATE, 삭제 = DELETE. URL 게이트(`/admin/faq/manage`·`/admin/api/faqs`·`/admin/api/faqs/**`·`/admin/api/faq-categories`·`/admin/api/faq-categories/**`)는 `AdminFeature.FAQ.gatePatterns`에서 `SecurityConfig`의 `DELEGABLE` 루프가 만든다(관리 쪽 `SecurityConfig` 수정 없음). 배너·팝업·정적 페이지 권한과 서로 독립이다(`FaqPermissionMatrixIntegrationTest`). 화면 버튼은 `myPermissions`(`"FAQ:CREATE"` 등)로 숨길 뿐 서버 판정(403)이 최종이다. **새 `DELEGABLE` 기능을 추가하면 열거하는 시험이 함께 바뀐다**: `AdminSidebarAdviceSnapshotTest`·`AdminPermissionEvaluatorTest`(ADMIN 전 동작 키)·`MenuExposureSidebarIntegrationTest`(위임 READ 시드는 카탈로그에서 생성).
- **스키마(V41~V42)**: `faq_category`(이름 50자·`ord`·`use_yn`)·`faq`(`category_id` FK **RESTRICT**·질문 300자·`answer_html` MEDIUMTEXT·`ord`·`use_yn`)·`faq_lock`(가드 행 id=1 + `version`). 둘 다 **하드 삭제**, 연관관계 매핑 없이 `categoryId`만 가진다. 날짜 컬럼은 `datetime(6)`. 공개는 `카테고리.use_yn ∧ FAQ.use_yn`이고 카테고리를 숨기면 그 안의 FAQ가 모두 숨는다.
- **동시성 — 모든 쓰기 메서드의 첫 DB 조회가 가드 행 `faq_lock` `FOR UPDATE`** (`FaqService.lockGuard`): 규칙이 하나(가드 → 끝)라 교착 추론이 필요 없고 행 락·`@Version`이 필요 없다. 비잠금 읽기(`count`·최대 `ord`·목록)는 가드를 잡은 **뒤에** 한다. 가드 행이 없으면 `IllegalStateException`(500) — 조용히 잠금 없이 진행하지 않는다. 이름·질문·답변·노출만 바뀌는 수정도 가드를 잡지만 `version`은 올리지 않는다. **`version`은 구조가 바뀔 때만 +1**: 카테고리·FAQ 등록·삭제, FAQ의 카테고리 이동, **실제로 바뀐** 순서 반영. 시험: `FaqConcurrencyIntegrationTest`(`LockWaitObserver` 락 대기 관측, 빈 테이블 12개 동시 등록 = `ord` 0..11·버전 +12, 상한 직전 6개 동시 등록 = 정확히 하나만, 같은 version으로 서로 다른 순서를 동시 반영 = 정확히 하나만 성공·하나 409). **변이 실험으로 `lockGuard()`를 잠금 없는 `findById`로 바꾸면 3건이 실패함을 확인**했다(락 대기 시험은 `bumpVersion`의 UPDATE가 같은 행을 잠그므로 변이에서도 통과 — 정확한 상한·`ord` 유일·순서 경합 시험이 검출한다).
- **조회는 version과 트리를 한 읽기 트랜잭션(같은 REPEATABLE READ 스냅샷)에서 읽는다**(`getTree`, 잠금 없음): 쓰기만 직렬화해서는 "옛 순서 + 새 version" 응답을 막지 못하고, 그 응답으로 만든 순서 초안은 다른 관리자의 변경을 409 없이 덮는다(`treeRead_versionAndOrderComeFromOneSnapshot`가 순서 반영이 계속 커밋되는 동안 version 짝홀과 순서의 일치를 본다).
- **`ord` 불변식: 각 부모(카테고리는 전체, FAQ는 카테고리)의 `ord`는 항상 정확히 0..n-1**: 등록은 맨 끝, **삭제·카테고리 이동은 영향받은 목록을 같은 트랜잭션에서 즉시 재번호**(값이 다른 행만 쓴다), 이동한 FAQ는 대상 카테고리의 맨 끝에 들어간다. 배너는 삭제 후 압축하지 않지만(순서 저장이 한 번에 고친다) FAQ는 "같은 순서 재저장 = 쓰기·버전 없음"이 값 비교에 기대므로 연속성을 항상 유지한다.
- **상한은 정확하다**: 카테고리 30·FAQ 200(초과 409). 가드로 직렬화되므로 동시 등록에도 넘지 않는다(팝업의 소프트 상한과 다르다).
- **순서 반영 `PUT /admin/api/faqs/order`**: 요청 `{version, categories:[{id, faqIds:[…]}]}` — 전체 카테고리 순서와 각 카테고리의 전체 FAQ 순서. 검사 순서: 형식(중복) 400 → 가드 잠금 → **`version` 불일치 409** → 집합이 현재와 다르면 **400**(버전이 같은데 집합이 다르면 클라이언트 오류 — 다른 카테고리로 옮기는 요청도 여기서 400) → 값이 다른 행만 쓰고 **바뀐 것이 있을 때만** 버전 +1 → 응답은 같은 트랜잭션에서 만든 새 트리. **카테고리 간 이동은 FAQ 수정(`categoryId` 변경)으로만** 한다. `PUT /order`와 `PUT /{id}`는 같은 컨트롤러에 있고 리터럴 경로가 우선하며 `FaqApiIntegrationTest.routing_orderVersusId`가 고정한다.
- **API 응답과 감사**: 등록·수정·삭제 서비스는 최상위 `getId()`를 가진 결과(`FaqResponse`·`FaqCategoryResponse`)를 돌려준다 — 감사 Aspect가 **반환 객체의 최상위 숫자 getter**로만 `targetId`를 뽑기 때문이다(트리만 돌려주면 `targetId=null`로 조용히 누락). 등록 응답은 트리가 아니라 **생성된 항목**이고 화면이 `GET`으로 트리를 다시 읽는다. 감사: `FAQ_CREATE`·`FAQ_UPDATE`·`FAQ_DELETE`(`targetType=FAQ`), `FAQ_CATEGORY_*`(`targetType=FAQ_CATEGORY`), `FAQ_ORDER`(`targetId` 없음). 질문·이름·답변은 사용자 입력이라 `targetLabel` 없음, 실패 행 `errorMessage`는 고정 문구(`safeErrorMessage`)다. `AdminActionTypes`와 `templates/admin/log/manage.html` 라벨은 동기화 시험이 고정한다.
- **답변 본문**: `ContentBodyPolicy.sanitizeFaq`(**이미지 불허** — 본문 이미지 공개 판정에 FAQ를 끌어들이지 않으려고, 보이는 글자 5,000자, 정리 후 30,000바이트, 요청 원문 60,000바이트(`@MaxUtf8Bytes`로 파싱 전에 거름))와 출력 시 재정리 `sanitizeForFaqOutput`(결과의 `SanitizedHtml.blank()`가 참이면 공개에서 건너뜀). 편집기는 `NoticeEditor.create(…, {allowImages:false})`다.
- **카테고리 삭제**는 FAQ가 하나라도 있으면 409(먼저 옮기거나 지운다). 존재하지 않는 카테고리를 FAQ 등록·이동에 지정하면 **400**(본문 참조 오류), 대상 FAQ·카테고리 자체가 없으면 404.
- **화면**(`templates/admin/faq/manage.html`): 왼쪽 카테고리 카드 안에 FAQ 행, 오른쪽에 카테고리 폼·FAQ 폼(편집기). 순서는 **새 라이브러리 없이 네이티브 HTML5 드래그 + ▲▼ 버튼**이 같은 **초안**(`order`)을 바꾸고 [순서 반영]이 `PUT /order`를 보낸다([취소]는 서버 상태로). 같은 카테고리 안 FAQ와 카테고리 순서만 끈다(드롭은 `dragstart`의 종류·카테고리가 같은 대상에서만 `preventDefault`). 상태 플래그: `busy`(쓰기 요청부터 후속 목록 갱신 완료까지·목록 조회 중), `loadingDetail`, `syncFailed`, 초안 `isDirty()`. **잠금 규칙**: 목록 조작(드래그·▲▼·[반영])은 `busy`/`loadingDetail`/`syncFailed` 중 막히고 **이벤트 핸들러 안에서도 검사**한다(버튼 `disabled`만 믿지 않음). 폼 전체(`fieldset`)와 Quill 편집기(`editor.quill.enable(false)`)는 위에 **초안이 있는 동안**도 잠근다(재조회가 초안을 지우므로). 목록 GET은 요청 세대(`loadSeq`)를 갖고 초안이 시작되면 세대를 올려 이전 응답을 폐기한다. **잠금 상태가 바뀌면 `sync()`로 목록을 다시 그려야 한다** — 손잡이(`draggable`)·▲▼의 활성 여부가 그리는 시점의 잠금으로 정해져, 목록 조회 중에 그려진 화면이 조회 뒤에도 잠긴 채 남는 결함을 브라우저 시험이 잡았다. **쓰기 결과와 목록 동기화를 분리**한다: 쓰기 2xx 뒤 재조회가 실패하면 `syncFailed`("저장은 완료됐지만 …")로 [새로고침]만 허용, 쓰기 응답을 잃으면 "저장 여부를 확인할 수 없습니다 … 직접 확인"으로 폼을 잠그고 **자동 재전송하지 않는다**(멱등 키는 두지 않았다 — 수용한 한계). 409(낡은 화면·상한·자식 있는 카테고리)면 서버 메시지 + 최신 목록 재조회(초안 폐기), 400이면 초안을 남긴다. 이름·질문은 `textContent`로만 삽입. 메서드 보안 403의 `message`가 영문이라 고정 한국어 문구를 쓴다.
- **롤백 후 권한 부활**: FAQ 도입 전 앱으로 롤백했다가 재배포하면 이전 앱의 "전체 회수"가 남긴 `FAQ` 행이 되살아난다 — `docs/deployment.md` "FAQ"의 정리 트랜잭션이 필수. `faq_lock` 가드 행은 지우지 않는다(없으면 FAQ 쓰기가 전부 500).
- **수용한 한계**: FAQ **항목** 단건 수정의 질문·답변 stale-form 덮어쓰기는 수용한다(카테고리 수정은 PR ③부터 `version`으로 막고, 항목의 **소속 카테고리**는 `baseCategoryId`로 막는다). 네이티브 DnD는 터치 기기에서 동작하지 않아 ▲▼를 함께 둔다. 쓰기 응답이 유실된 뒤의 늦은 커밋은 막지 않는다(재조회가 성공해도 원래 요청이 뒤늦게 커밋될 수 있다 — 다른 관리 CRUD와 같은 한계). DB를 직접 수정하면 `version`이 올라가지 않아 낡은 순서 초안이 409 없이 저장될 수 있다(`docs/deployment.md`에 SQL 수정 시 `version`을 올리는 절차).
- 시험: `FaqApiIntegrationTest`(생명주기·검증·상한·`ord` 연속성·이동·카테고리 삭제·순서 반영 409/400/no-op·감사 `targetId`=`Location` ID·고정 오류 문구)·`FaqPermissionMatrixIntegrationTest`(핸들러 9 × 권한 7조합)·`FaqConcurrencyIntegrationTest`·`FaqMigrationTest`, **`FaqAdminOrderBrowserTest`(실제 브라우저 — 네이티브 드래그·▲▼·취소·낡은 초안 409·요청 중 잠금·상세 로딩 중 폼 잠금·쓰기 성공 뒤 재조회 실패 복구·응답 유실, `src/test/java`의 `CLAUDE.md` "브라우저 기본 동작")**, 그리고 `com.cms.config`의 `SecurityConfigTest` FAQ 판.
- **사이트별 표시 대상(PR ③, 2026-10-13)**: `faq_category.site_id`(NULL = 공통)·`faq_category.version`(V55) — FAQ 항목은 카테고리를 따른다. 카테고리 등록은 `siteScope` 선택, **수정은 별도 `FaqCategoryUpdateRequest`(`siteScope`·`version` 필수)**. 항목 수정은 `baseCategoryId` 필수(현재 소속과 다르면 409). 트리 응답(`FaqTreeResponse.Category`)에도 `siteId`·`version`이 있다 — 화면의 편집 입력원이 트리라서다. 상세는 `com.cms.admin.site`의 `CLAUDE.md` "사이트별 콘텐츠".
