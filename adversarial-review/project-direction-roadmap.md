## 현재 상태 진단

**한 줄 요약: 관리자 백오피스·콘텐츠 도메인·공개 사이트를 갖춘 CMS가 됐다. 남은 간극은 "실제로 운영해 본 적이 없다"는 것이다.** 최초 진단(2026-07-10)의 "콘텐츠가 없는 백오피스 골격"과 공백 다섯 가지는 모두 해소됐다.

### 강점 (계속 유지할 것)

- **콘텐츠와 공개 사이트가 있다.** 범용 게시판(공지 흡수·예약 게시·휴지통·유형), 정적 페이지, 배너·팝업, FAQ, 문의함, 미디어 라이브러리, 편집기 본문 이미지를 관리하고, 사이트별 공개 경로(`/{siteKey}/…`)로 내보낸다.
- **규약을 시험으로 강제한다.** `AdminPageAnnotationConventionTest`·`ClockUsageConventionTest`·`LocaleRootConventionTest` 등 컨벤션 시험이 코드 규칙을 지키게 하고, CI가 `test`·`browser-test`·`prod-smoke`(prod 이미지 기동·백업복구 왕복·이미지 스캔)를 매 PR 확인한다.
- **횡단 관심사가 성숙하다.** AOP 감사 로깅(독립 트랜잭션·예외 격리), 전 경로 CSRF, 기본 거부(`anyRequest().denyAll()`), 무인증 공개 경로 레이트리밋, MANAGER 기능·게시판 단위 위임 권한, HTML sanitizer 단일 경로.
- **기록 문화**: 계획서와 적대적 리뷰, 패키지별 `CLAUDE.md`, `docs/troubleshooting.md`, Flyway 마이그레이션 이력. 이 습관이 프로젝트의 가장 큰 자산이다.

### 공백 (방향성을 정하는 제약)

1. **실배포가 없다.** prod 이미지는 배포 가능 상태까지 검증했지만, 리버스 프록시·TLS·호스팅이 정해지지 않아 운영 경험(모니터링, 오프사이트 백업, 실제 메일·캡차 키, 운영망 외부 호출)이 검증되지 않았다 — 마일스톤 "실배포 준비".
2. **운영 요구가 확인되지 않았다.** 감사 로그 내보내기·초대 가입·2단계 인증 같은 운영 편의·보안 강화 항목은 실제 운영 요구를 본 뒤 정하려고 보류했다 — 라벨 `deferred`.

## 할 일 보는 곳

- **실배포 준비**: 마일스톤 [실배포 준비](https://github.com/Noname-dev01/CMS/milestone/1) — 실제 인터넷 배포와 운영 투입 전 작업
- **선행 조건 대기**: 라벨 `blocked` — 호스트·도메인·키 등이 정해져야 착수할 수 있는 항목
- **재평가 보류**: 라벨 `deferred` — 착수 조건이 생기면 다시 본다
- 새 할 일은 이슈 템플릿 "로드맵 항목"으로 등록한다. 완료는 PR 본문의 `Closes #N`으로 닫는다. 완료 기준을 일부만 채운 PR은 `Refs #N`을 쓰고 남은 항목을 적는다.

## 단계별 방향

- **1단계 기반 마감·2단계 첫 콘텐츠 도메인**: 끝났다. 기록은 보관 파일의 "3단계 로드맵"과 "실행 로드맵 — …" 섹션에 있다.
- **3단계 운영 경험**: 진행 중이다. 남은 핵심은 실배포(호스트·도메인·TLS)이고, 운영 투입 전 작업은 마일스톤 "실배포 준비"에 모았다.
- **QueryDSL 원본(5.1.0) 유지**: 개발이 사실상 멈춘 라이브러리지만, Boot 4.0.8 이행(#97) 때 Hibernate 7.2에서 동작함을 확인해 OpenFeign 포크 전환은 보류했다. Hibernate 마이너 상향이나 QueryDSL 결함이 드러나면 재평가한다(보관 파일 "지속 항목").
- **`accessRole` 인가 연동은 종료**(2026-11-12 확인): 메뉴의 역할 필드를 인가에 반영하자는 항목이었지만, 기능 권한 카탈로그·판정기(#81)와 판정기 기반 사이드바 노출(#82, `MenuVisibility`)로 대체됐고 `access_role` 컬럼은 #84에서 제거됐다. 지금은 낡은 클라이언트가 보내는 `accessRole`을 조용히 무시하는 호환 계약만 남아 있다(`MenuControllerTest.createMenu_legacyAccessRoleIgnored`).
