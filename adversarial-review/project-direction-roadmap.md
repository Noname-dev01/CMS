## 현재 상태 진단

**한 줄 요약: "CMS"라는 이름과 달리, 지금 이 프로젝트는 콘텐츠가 없는 잘 만든 관리자 백오피스 골격이다.** 이 간극을 어떻게 메울지가 방향성의 핵심이다.

### 강점 (계속 유지할 것)

- **공학적 규율이 좋다.** 계층 분리, DTO 경계, 생성자 주입, QueryDSL 동적 쿼리, 전역 예외 처리까지 일관성이 있고, `AdminPageAnnotationConventionTest`처럼 컨벤션 자체를 테스트로 강제하고 있다.
- **횡단 관심사가 이미 성숙하다.** AOP 감사 로깅(REQUIRES_NEW 독립 트랜잭션 + 예외 격리), CSRF 전면 활성화, API 경로 JSON 401/403 분기(CSRF 필터 순서로 인한 401/403 오분류까지 처리 — `SecurityConfig.java:69-72`), ADMIN/MANAGER 역할 세분화 완료.
- **기록 문화**: 트러블슈팅 24건, 마이그레이션 SQL 기록, CI + GitHub Flow. 이 습관이 프로젝트의 가장 큰 자산이다.

## 할 일 보는 곳

- **실배포 준비**: 마일스톤 [실배포 준비](https://github.com/Noname-dev01/CMS/milestone/1) — 실제 인터넷 배포와 운영 투입 전 작업
- **선행 조건 대기**: 라벨 `blocked` — 호스트·도메인·키 등이 정해져야 착수할 수 있는 항목
- **재평가 보류**: 라벨 `deferred` — 착수 조건이 생기면 다시 본다
- 새 할 일은 이슈 템플릿 "로드맵 항목"으로 등록한다. 완료는 PR 본문의 `Closes #N`으로 닫는다. 완료 기준을 일부만 채운 PR은 `Refs #N`을 쓰고 남은 항목을 적는다.

## 단계별 방향

- **1단계 기반 마감·2단계 첫 콘텐츠 도메인**: 끝났다. 기록은 보관 파일의 "3단계 로드맵"과 "실행 로드맵 — …" 섹션에 있다.
- **3단계 운영 경험**: 진행 중이다. 남은 핵심은 실배포(호스트·도메인·TLS)이고, 운영 투입 전 작업은 마일스톤 "실배포 준비"에 모았다.
- **재평가가 끝나지 않은 기술 방향**: QueryDSL OpenFeign 포크 전환과 `accessRole` 인가 연동. 확인한 뒤 이슈로 만들거나 종료한다(보관 파일 "지속 항목"·"선정에서 탈락한 후보").
