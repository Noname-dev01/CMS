# 계획 적대적 리뷰 루프

대상 계획 문서: $ARGUMENTS (비어 있으면 `adversarial-review/plan/`에서 가장 최근 수정된 `PLAN-*.md`를 대상으로 하고 — 없으면 `adversarial-review/` 직하의 구형 `*-plan.md`까지 후보에 포함 — 어느 파일인지 먼저 보고한다.)

## 상시 규칙 (매 라운드 공통 — 사용자가 다시 말하지 않아도 항상 적용)

- 모든 출력은 **한국어**. 리뷰 원문이 영어면 전체를 한국어로 번역해 보여준다 (코드 식별자·기술 용어는 원형 유지, 누락·축약 금지).
- 확인되지 않거나 확실하지 않은 부분은 **추측하지 말고 사용자에게 질문**한다.
- 사용자가 결정해야 하는 트레이드오프는 선택지로 정리해 질문한다.
- 리뷰 결과는 **원문 전체를 먼저 보여준 뒤** 트리아지한다. 요약만 제시하고 원문을 생략하지 않는다.

## 라운드 절차

1. **[리뷰 요청]** 계획 문서 본문을 읽는다. 그 다음:
   - `codex` CLI를 쓸 수 있으면 (`codex:codex-cli-runtime` 스킬 계약 참조) 비대화형으로 적대적 리뷰를 요청한다.
     프롬프트에 **계획 문서 전문을 반드시 포함**한다 — repository context만 믿고 파일명만 넘기면
     "컨텍스트 없음"으로 빈 리뷰가 돌아온 전례가 있다(2026-06-18 실패 루프).
     요청 문구: "이 계획의 접근법에 의문을 제기하고, 숨겨진 가정·엣지케이스·실패 모드를 찾아라.
     실질적 지적이 없으면 ship 판정을 명시하라. 한국어로 답하라."
   - codex 호출이 실패하거나(분류기 차단 포함, 1회만 재시도) CLI가 없으면, **직접 적대적 리뷰를 수행**하고
     출처가 codex가 아닌 자체 리뷰임을 명시한다. 실패를 이유로 라운드를 중단하지 않는다.
2. **[원문 표시]** 리뷰 결과 전체를 한국어로 사용자에게 그대로 보여준다.
3. **[트리아지]** 지적별로 원문을 인용하고 판단을 붙인다:
   - **수용** (타당) → 계획에 반영 + 변경점 명시
   - **반박** (부당/과함) → 근거와 함께 기각 사유 기록
   - **결정 필요** → 선택지로 정리해 사용자에게 질문하고, 답을 받을 때까지 해당 항목 반영 보류
4. **[반영]** 수용 항목을 계획 문서에 반영하고, 문서 상단 개정 이력에 `vN 변경: ...` 형식으로 남긴다.
   기각 항목도 "기각: <사유>"로 이력에 남겨 다음 라운드 리뷰어가 같은 지적을 반복하지 않게 한다.
5. **[종료 판정]** 다음 중 하나면 루프를 멈추고 결과를 보고한다. 아니면 1로 돌아가 다음 라운드를 자동 진행한다:
   - 리뷰가 실질적 지적 없이 **ship 판정**을 냈다 → "리뷰 통과. 구현을 진행할까?"라고 질문
   - 새 지적이 전부 이전 라운드에서 기각·수용된 내용의 반복이다 → 동일하게 ship 처리
   - **결정 필요** 항목이 나왔다 → 질문 후 대기
   - 5라운드에 도달했다 → 남은 쟁점을 정리해 보고하고 계속할지 질문

## 금지 사항

- 사용자 승인 없이 계획 문서 이외의 코드를 수정하지 않는다 (구현 착수는 별도 지시/승인 필요).
- 리뷰 지적의 무비판 수용 금지 — 모든 수용에는 "왜 타당한지"를 한 줄이라도 붙인다.
- 라운드 사이에 `/clear`를 요구하지 않는다. 컨텍스트가 길어지면 계획 문서와 개정 이력이 상태의 원본이므로 그대로 이어간다.
